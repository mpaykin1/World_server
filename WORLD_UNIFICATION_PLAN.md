# World Unification Plan

Цель: ни один мир не теряется; каждый графический мир автоматически проверяется до публикации; все миры связаны одной историей и единым минимальным интерфейсом.

## История: «Осколки Improve World»
После сбоя World Server единый мир раскололся на осколки. Навигатор — живой глаз-проводник — помнит, что все миры были одним целым. Каждый мир хранит отдельный слой общей реальности: память, город, выживание, музыку, эксперименты и сны. Игрок проходит миры, собирает «следы», а центральный мир постепенно восстанавливается и меняется от действий игроков.

## Фазы
- [x] 0. Единый реестр миров и сохранение legacy Vercel URL.
- [x] 0.1. Golden Standard: WASD + стрелки + mobile movement/look для сертифицированных миров.
- [ ] 1. Автоматический fleet-audit ВСЕХ графических миров.
- [ ] 1.1. Проверка: страница открылась, нет fatal runtime error.
- [ ] 1.2. Проверка: графика реально появилась и кадр не пустой.
- [ ] 1.3. Проверка: WASD реально меняет состояние/кадр.
- [ ] 1.4. Проверка: стрелки реально меняют состояние/кадр.
- [ ] 1.5. Проверка: mobile joystick реально двигает игрока.
- [ ] 1.6. Проверка: mobile look/camera реально меняет камеру.
- [ ] 1.7. JSON-отчёт PASS/FAIL/BLOCKED по каждому миру с причиной.
- [ ] 2. Починить все FAIL/BLOCKED, не скрывая миры.
- [ ] 3. Один общий сюжет и переходы между мирами.
- [ ] 4. Один маленький верхний контрол «Миры» вместо ряда кнопок.
- [ ] 4.1. Убрать лишние постоянные кнопки; каталог открывать оверлеем.
- [ ] 4.2. В каждом мире всегда есть путь назад в общий мир/каталог.
- [ ] 5. Сквозная история: прогресс/следы игрока переносятся между мирами.
- [ ] 5.1. Миры получают роли в общей истории, не теряя существующую графику и механику.
- [ ] 6. Полный E2E: desktop Chrome + mobile Chromium + mobile WebKit.
- [ ] 6.1. Каталог -> каждый мир -> управление -> возврат -> следующий мир.
- [ ] 7. Release gate: новый/изменённый мир не публикуется при FAIL.
- [ ] 8. Автоматический повторный аудит после изменения мира и перед релизом.

## Правила
1. FAIL означает чинить первопричину, а не убирать мир из каталога.
2. Старые deployments остаются в реестре как история/резерв, пока не подтверждена миграция.
3. Никакого ручного списка кнопок: UI строится из единого реестра.
4. Графику, физику, анимации и звук не упрощать ради тестов.
5. PASS засчитывается только при измеримом доказательстве, не по наличию DOM-элемента.
6. Этот файл — контрольный план. После каждой фазы обновлять чекбоксы и сохранять evidence в отчёте аудита.
