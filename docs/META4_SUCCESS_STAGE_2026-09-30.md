**Дата фиксации:** 30 сентября 2026

Этот документ нужен как обучающий handoff для следующих чатов и агентов. Он фиксирует не только то, что получилось, но и **почему получилось**, какие ошибки были устранены и какие свойства нельзя потерять при дальнейшем развитии.

## 1. Что мы строим

Meta4 — лёгкий вертикальный прототип режима «Цепная реакция» / World Consequence Engine. Игрок видит бесконечное процедурное пространство, двигает мир пальцем, выбирает действия-иероглифы, получает прогноз последствий, подтверждает изменение мира, наблюдает изменение ресурсов и движение людей, а затем читает отчёт о текущей видимой области.

Meta4 не является отдельной заменой World Server. Это минимальный проверяемый UX/симуляционный прототип, который должен переносить удачные механики обратно в основную архитектуру World Server.

## 2. Что пользователь признал успешным

Пользователь подтвердил этот этап как успешный после исправления четырёх связанных проблем:

1. игровой экран на мобильном больше не «гуляет» вместе со страницей;
2. после перемещения камеры новая постройка появляется **там, куда игрок переместился**, то есть внутри текущей видимой области;
3. люди начинают мигрировать к новым причинам притяжения, например к удалённому городу;
4. отчёт описывает текущую видимую область, а не весь мир одновременно.

Также сохранились:
- бесконечное перемещение мира;
- фиксированный HUD;
- пять карточек действий с автоматической выдачей новой пятёрки после использования;
- окно прогноза «Да / Нет» перед изменением мира;
- публичная GitHub Pages версия без срока годности.

## 3. Главный технический успех: разделение world-space и screen-space

Решающим исправлением стало прекращение смешивания мировых координат и координат экрана.

Канонические преобразования:

    screen = viewportCenter + cameraOffset + world
    world = screen - viewportCenter - cameraOffset

Объекты, люди и события хранятся в **world-space**. Камера лишь определяет, какую часть world-space видно сейчас.

Когда игрок перемещает мир, меняется только `cameraOffset`. Когда он создаёт новый объект, точка сначала выбирается внутри текущего playable rectangle в screen-space, а затем переводится обратно в world-space.

### Почему это сработало

Раньше объект создавался через случайный радиус вокруг мирового origin. После дальнего pan origin уже находился далеко за пределами экрана, поэтому новая постройка появлялась «невидимо».

Исправленный placement:

1. вычисляет реально свободную видимую область между верхним HUD и нижней панелью карточек;
2. выбирает безопасную точку внутри неё;
3. переводит эту точку через `screenToWorld()`;
4. сохраняет объект уже в world-space;
5. отображает его через `worldToScreen()`.

Это превращает бесконечный pan из визуального трюка в настоящую систему координат мира.

## 4. Второй технический успех: неподвижная игровая поверхность на iPhone

Успешная версия фиксирует документ и отдаёт жесты игре:

- `html, body { position: fixed; inset: 0; overflow: hidden; }`
- `overscroll-behavior: none`
- `touch-action: none` на игровой поверхности
- non-passive suppression нативного `touchmove` вне специально прокручиваемых модальных окон
- pointer capture во время drag
- HUD живёт в screen-space и не зависит от камеры
- scroll разрешён только внутри содержимого длинной модалки отчёта

### Почему это сработало

Проблема была не в скорости pan, а в неправильном владельце жеста: браузер и игра одновременно пытались интерпретировать движение пальца.

После разделения ответственности:
- браузер не прокручивает документ;
- игра получает pointer/touch;
- камера сдвигает мир;
- интерфейс остаётся визуально закреплён.

Это ближе по ощущению к стратегиям вроде OpenTTD/Micropolis: игрок перемещает карту внутри игрового окна, а не страницу вокруг игры.

## 5. Третий успех: причинная миграция

Люди перестали быть декоративными точками, вращающимися около старого центра.

Каждый житель теперь имеет world-space позицию, скорость и потенциальную цель. Разные сущности создают разные причины миграции:

- город / дом / община — сильное притяжение;
- рынок / мастерская / школа — работа и услуги;
- вода / река / поля — ресурсы;
- лес / сад — более слабое притяжение;
- вулкан / опасный огонь — локальное отталкивание.

После создания удалённого города часть населения получает его как migration target и постепенно движется к нему. Новые жители, появившиеся из-за постройки, создаются около причины роста, а не около нулевого центра.

### Почему это важно

Это первый шаг от «иконки меняют цифры» к живому причинному миру:

    действие игрока
    -> новый объект
    -> новая причина
    -> изменение поведения жителей
    -> наблюдаемая миграция
    -> новый локальный контекст мира

Именно такие причинные цепочки должны масштабироваться в World Server.

## 6. Четвёртый успех: viewport-local report

Отчёт теперь отвечает на вопрос **«что происходит здесь, где я сейчас смотрю?»**.

Он фильтрует:
- людей, находящихся в текущем viewport;
- видимые объекты;
- локальный суммарный эффект этих объектов;
- жителей, мигрирующих к местным точкам притяжения;
- последние события, координаты которых находятся в текущей видимой области.

### Почему это сработало

До исправления отчёт был глобальным и поэтому разрушал смысл бесконечной карты: игрок мог уйти очень далеко, но продолжал читать историю старого центра.

Локальная фильтрация делает камеру не просто навигацией, а **контекстом наблюдения**.

Для будущих систем это важный принцип:

> Camera/viewport может определять контекст интерфейса, отчёта, AI-запроса, локальных событий и выбора объектов — но не должен менять каноническое world-state.

## 7. Продолжение карточек работает как минимальный бесконечный loop

В Meta4 есть каталог действий, а UI показывает по пять карточек. После расходования всех пяти выдаётся следующая пятёрка без перезагрузки.

Это удачный минимальный паттерн:
- пользователь всегда имеет ограниченный понятный набор действий;
- игра может иметь большой/бесконечный каталог;
- UI не захламляется;
- новые действия создают ощущение развития;
- логика выдачи отделена от мира и может позже заменяться «Злым Джинном» или настоящим AI.

## 10. Антипаттерны, которые нельзя повторять

### Нельзя: строить относительно origin

Плохой паттерн:

    angle = random()
    radius = random()
    object.x = cos(angle) * radius
    object.y = sin(angle) * radius

если `object.x/y` никак не учитывают текущую видимую область.

Он визуально работает только пока камера рядом с origin.

### Нельзя: хранить людей в screen-space

Иначе миграция ломается при pan: человек «едет вместе с камерой» вместо того, чтобы существовать в мире.

### Нельзя: считать бесконечным мир, в котором бесконечен только фон

Бесконечность считается реализованной только если placement, entities, reports, simulation и причинные связи продолжают работать после большого pan.

### Нельзя: давать глобальный отчёт под названием «что происходит здесь»

Локальный и глобальный отчёт — разные продукты.

### Нельзя: считать мобильный drag исправленным только по CSS

Нужна проверка реальным жестом: camera delta > 0, document scroll = 0, HUD delta = 0.

## 11. Граница этого успеха

Важно не переоценивать этап.

**Meta4 пока не использует настоящий AI для карточек прогноза.** Текущий `forecastFor()` — локальная детерминированная эвристика.

На World Server отдельно уже работает production endpoint:

https://world-server.mmmpaykin.workers.dev/api/chain-ai

и живые проверки подтвердили Groq и Cloudflare AI. Следующий правильный вертикальный шаг — соединить удачный Meta4 UX с реальным `predict_build` API, сохранив критическое правило:

    choose action
    -> choose current visible location
    -> snapshot current authoritative context
    -> AI prediction, executed:false
    -> modal NO / YES
    -> only YES mutates the world

Нельзя заранее строить объект, откатывать его после NO или позволять AI самому изменять world-state.

## 12. Что должен сделать следующий чат

Следующий разработчик не должен начинать прототип заново.

1. Открыть живую Meta4 и проверить exact commit.
2. Прочитать этот документ и mobile viewport contract.
3. Сохранить spatial модель Meta4 без регрессий.
4. Подключить реальный World Server `/api/chain-ai` в prediction-only режиме.
5. Передавать в AI контекст **текущей видимой области плюс необходимые глобальные ресурсы**, явно различая local/global данные.
6. На NO не менять никакое состояние.
7. На YES размещать ровно один объект внутри выбранного/текущего viewport.
8. После строительства причинная миграция и локальный отчёт должны продолжать работать.
9. Проверять на физическом iPhone, а не только в desktop emulation.
10. Любой дальнейший успех или неудачу оформлять отдельным learning record с exact SHA, evidence и причиной результата.

## 13. Короткая формула успешного этапа

Meta4 стала успешной не потому, что «добавили pan».

Она стала успешной, когда одна пространственная модель одновременно начала управлять:

**камерой → размещением → симуляционными сущностями → миграцией → локальным отчётом → мобильным вводом.**

Это и есть главный переносимый урок данного этапа.
