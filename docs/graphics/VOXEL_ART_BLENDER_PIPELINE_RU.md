# Оригинальная воксельная графика World Server: Blender 5.1 → glTF → игра

## Цель
Собственная графика «Цепной реакции»: никаких Minecraft-скриншотов, скопированных
текстур или чужих игровых моделей. Вход — выбранный художником/ИИ концепт,
выход — повторяемые CPU-генератором Blender исходники и готовые GLB с клипами.
Арт-дирекшн: кубический уютный индустриальный мир, зелёные леса, оранжевые крыши,
бирюзовая техномагия, работающие механизмы, читаемые изометрические силуэты.

Основа — архив пользователя «Материалы к видео по астре.rar»:
Gamedesign/art-direction.md, 3d-asset-pipeline.md и «Гайд.pdf». Лицензия
вложенных референсов неизвестна; **сами референсы не импортируются в игру**.
Семь этапов адаптированы для самостоятельной работы ИИ с автопроверками:
ТЗ → концепт → лист проекций → модель/материалы → клипы →
VFX → упаковка/повторный импорт. Художественное согласование требуется для
изменения утверждённого визуального эталона, но не блокирует повторяемую
техническую генерацию уже одобренных типов объектов.

## Конвейер
- Источник: tools/voxel-art/generate_blender.py.
- Восемь оригинальных моделей: barren, city, forest, volcano,
  energy, idea, river, villager.
- Формат — glTF 2.0 binary (.glb), Y-up, метры, оригинальные PBR-материалы.
- Анимация: ветряная турбина, парящий кристалл, вулканические искры.
  Хуки дополнительных VFX перечислены в манифесте; эффекты пепла, дыма,
  речных брызг и электричества подключать к существующему CPU sprite runtime
  по событиям симулятора, а не запускать постоянно.
- apps/voxel-world/voxel-art/manifest.json: SHA-256 каждого файла,
  число полигонов, размер, названия клипов, лицензия, VFX-хуки.
- shared/graphics/voxel-art-contract.mjs: контракт макрообъектов.
- apps/voxel-world/voxel-art-runtime.mjs: GLTFLoader, AnimationMixer,
  загрузка по требованию, лимит 6 моделей mobile / 10 desktop,
  отсечение за пределами камеры, fallback к обычному рендереру.

На Windows:

    cd C:\Users\user\Desktop\World_server
    npm run voxel-art:generate
    npm run voxel-art:verify

Команда voxel-art:generate ищет Blender 5.1+ через BLENDER_BIN или стандартный
путь, не пользуется платными API, не загружает чужие игровые изображения.
Для отдельных ассетов:

    blender -b --factory-startup --python tools/voxel-art/generate_blender.py -- --out apps/voxel-world/voxel-art --kinds city,forest,volcano --preview

--preview требует доступного локального рендера. При сбое превью остаются
GLB и валидируемый манифест.

## Подключение к игровому рендереру
Оригинальный GLB-слой включается флагом ?voxelArt=1 и использует уже
существующие сохранённые макрообъекты emergenceState.entities.
Без флага старые сцены не меняются. Переходить на постоянный слой только
после независимых скриншотов desktop + mobile и визуального согласования;
новый слой не должен самовольно изменять балансы и физику игры.

Конвейер не умеет пока по произвольному тексту генерировать новую топологию:
в этой фазе текстовый сценарий выбирает проверенный тип модели. Для
произвольных новых существ и зданий нужны модель и художественный контроль.
Это воспроизводимый фундамент для будущей работы Blender-агента.

## MCP: опциональная надстройка
Официальный сервер: https://www.blender.org/lab/mcp-server/
Исходный код: https://projects.blender.org/lab/blender_mcp

Blender MCP позволяет агенту управлять живой Blender-сценой,
выполняя Python (bpy). **Официальное предупреждение:** у MCP нет защит
от удаления или утечки данных через выполненный Python-код.
Не включать автоматически на обычном ПК с личными файлами.
Размещать MCP только в отдельной VM с одноразовыми файлами,
TCP 127.0.0.1:9876, без внешнего порта и секретов.
Репозиторий не требует работающего MCP для публикации и генерации:
headless Blender работает без MCP и даёт повторяемую сборку.

## Готовность и публикация
Коммиты сами по себе не означают достижение 85% видимой готовности.
Нельзя выдавать публичную ссылку, пока нет доказательств: в браузере
видны собственные GLB при placement; анимации работают; сохранения
работают; подтверждены скриншоты и мобильный FPS; нет
регрессий управления, публикация соответствует exact SHA.
Порядок: unit/GLB check → визуальный preview → desktop/mobile E2E →
независимый review → exact-SHA staging → smoke POST.
