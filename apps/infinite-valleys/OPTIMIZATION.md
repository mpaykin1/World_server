# Бесконечные долины — правила рендеринга и оптимизации

**Назначение:** сверхдальний обзор на террасированные 3D-воксельные долины и каньоны с камерой, расположенной выше героя. Дальность горизонта важнее микрообъектов и детальных теней.

**Мир:** `/apps/infinite-valleys/` — автономный `index.html` (без Three.js, CDN, сервера и сетевых запросов). **Не менять** существующий `apps/voxel-world/client.js` и принятые миры. Это отдельный режим ландшафта.

## Приоритеты

1. Горизонт остаётся визуально непрерывным; сначала сокращать детализацию и разрешение, а не горизонт.
2. Ближние террасы должны быть узнаваемы и физически читаемы; герой стоит на твёрдой площадке и не проходит сквозь высокую ступень.
3. Игровая камера смотрит сверху вниз; большой обзор долин и протяжённые силуэты — основной художественный образ.
4. Цвета: белый/чёрный с допустимыми оттенками серого для стенок, освещённости и воздушной перспективы.
5. Минимум материалов, текстур, прозрачностей и экранных эффектов; атмосфера достигается формой рельефа и контрастом.
6. 60 FPS — целевой бюджет, 30 FPS — минимальный мобильный ориентир; ни FPS, ни дистанция не гарантируются без проверки на устройстве.

## Геометрия и рельеф

7. Главный объём вычисляется из детерминированной функции высоты `heightAt(x,z)`.
8. Высота квантована на фиксированные уровни: ступени создаются математически, не отдельными вложенными кубами.
9. Каньоны и русла рассчитываются из крупных непрерывных функций; удалённая геометрия не хранит объём под поверхностью.
10. Нельзя создавать скрытые внутренние грани.
11. Ближний объём: один инстанс на ячейку, только верхняя плоскость и боковые стенки террас.
12. Однотипные формы объединяются по инстансам; не выделять индивидуальные материалы для кубов.
13. Greedy Meshing разрешён как дальнейшая замена инстансов при доказанном снижении нагрузки, не как обязательство уже имеющегося рендера.
14. Для пещер/навесов можно отдельно подключать локальную полноценную воксельную структуру; удалённым долинам она не нужна.
15. Не плодить геометрию для элементов с проекцией меньше одного пикселя.

## Дальность и LOD

16. Ближайшая область: сетка 64×64 ячейки с шагом 4 единицы и отдельными инстансами террас.
17. Дальний рельеф: восемь вложенных квадратных колец с шагом 8, 16, 32, 64, 128, 256, 512, 1024 единицы.
18. Все кольца используют одну статическую индексированную сетку 64×64 с внутренним вырезом, вместо восьми независимо создаваемых сеток.
19. Удалённые уровни получают высоты прямо в вершинном GLSL-шейдере; CPU не строит дальние чанки.
20. В каждый кадр меняются только центр камеры и шаг кольца; сеточные буферы дальнего рельефа не перестраиваются.
21. Количество вершин зависит от фиксированного числа колец, а не растёт пропорционально площади обозримого мира.
22. Дальний горизонт плавно осветляется через атмосферное смешивание по расстоянию.
23. Объекты не появляются скачком при смене LOD: для будущих улучшений предусмотрены stitching, skirts или morphing.
24. Дальность ограничивается техническим дальним клипом (в текущем коде 45 500 единиц), а не обещанием «реальных 100 км».
25. Функция рельефа должна одинаково рассчитываться в JS (коллизии) и GLSL (рисование), иначе герой будет проваливаться.

## Рисование и материалы

26. WebGL2 + GLSL ES 3.0, без внешних зависимостей.
27. `antialias:false`, `alpha:false`, `depth:true` — экономить память буфера.
28. Не применять текстуры земли, normal maps, SSR, SSAO и тяжёлый bloom.
29. Не создавать динамические тени дальних гор и долин.
30. Локальный материал террас: светлые верхние площадки, тёмные вертикальные грани.
31. Дальний материал: освещение производными `dFdx/dFdy` и упрощённая яркость вместо физического света.
32. Воздушная перспектива и свет не должны скрывать форму долин.
33. Герой собирается в один геометрический буфер, не в десятки draw calls.
34. Небо рисуется одной полноэкранной геометрической примитивной операцией.
35. Устранять лишние отрисовки и расход GPU до добавления новых эффектов.

## Производительность

36. Ближняя сетка обновляется только после перемещения через границу ячейки, а не каждый кадр.
37. Для ближних инстансов используется один динамический GPU-буфер.
38. Дальние сетки, индексы и VAO создаются один раз при запуске.
39. CPU не генерирует десятки километров геометрии.
40. Не использовать полный wireframe: линии могут оказаться дороже обычных треугольников.
41. Максимум готовых буферов переиспользовать; не создавать новые массивы вершин в игровом цикле.
42. Отключать физику и ИИ удалённых существ (когда они будут добавлены).
43. Для самостоятельных новых объектов использовать аппаратное инстансирование.
44. Ограничивать число draw calls, пиксельное разрешение и количество вершин установленным бюджетом.
45. Использовать аппаратное отсечение граней/чанков только если оно корректно для конкретной сетки и измеримо полезно.
46. Измерять среднюю частоту кадров, а не утверждать скорость по одному мгновенному `dt`.
47. При перегрузке сначала снижать внутреннее разрешение рендеринга.
48. Затем при необходимости изменять плотность средних/дальних сеток, сохраняя силуэты горизонта.
49. Для огромных координат внедрять floating origin при появлении видимых проблем точности.
50. Рельеф по координатам должен воспроизводиться без сохранения всей карты в памяти.

## Дальнейшие допустимые усовершенствования

51. Screen-space error для динамического выбора LOD.
52. Frustum culling по чанкам, если дальние кольца будут разбиты на независимые блоки.
53. Horizon/occlusion culling только если стоимость вычисления меньше цены скрытого рельефа.
54. Асинхронная генерация ближних сложных объектов через Web Workers.
55. Кэш чанков и переиспользование GPU-буферов.
56. Priority streaming в направлении движения камеры.
57. Разделение частоты обновления мира и кадра.
58. Избирательное упрощение невидимых стенок террас.
59. Силуэтное дальнее пространство может быть дополнительно перенесено в аналитический raycast GLSL.
60. Нельзя выдавать будущие оптимизации за уже реализованные: каждое изменение должно быть проверено на целевых устройствах.

## Вход и управление

- ПК: WASD/стрелки — движение; Q/E — поворот; Shift — бег; Space — прыжок.
- Сенсорный экран: удерживать/вести одним пальцем — движение; двумя — камера; двойной тап — прыжок.
- В клиенте нет текстового HUD; диагностический счётчик доступен только с URL-хэшем `#stats`.
- Для запуска необходим WebGL2. Резервный Canvas 2D-рендер в этой версии **не реализован**.

## Не путать с реализованным

В текущем HTML реально есть фиксированные кольца LOD, инстансинг близких террас, процедурные высоты на GPU, минимальные материалы, туман по расстоянию, ограничение внутреннего разрешения и офлайн-исполнение. **Не реализованы** динамический greedy meshing, полноценная асинхронная генерация чанков, frustum/occlusion culling по чанкам, floating origin и аналитический raycasting. Это целевые правила, а не свойства текущего исполняемого файла.
