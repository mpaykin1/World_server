## 2. Жёсткие правила
- Ровно пять задач, новых не создавать. Один `cycle_id` и один PR на цикл.
- Каждая задача, меняющая `stage_completed`, в том же коммите переписывает `notes` одной строкой: этап, head SHA, блокер, следующий шаг.
- Нельзя: фиктивные PASS, пустые коммиты, handoff/evidence/отчётные файлы, новые тест-файлы (проверки — внутри кода, assert в скриптах).
- `remaining = 0` при `verified < applicable` — это FAIL «fake-complete». Каталог не засчитывает сам себя как интеграцию.
- Не трогать `**/stand/**`, `**/accepted/**`, V5–V7, `reference/sumerek-golden/`, принятые игры. Приватные репозитории — только общее число, без имён, путей и кода.
- В играх: только графика и иконки на экране, всё остальное в меню ☰ справа сверху.
- Нет `gh` — использовать GitHub API/коннектор. Платные API не подключать.
- Уведомлять владельца только ссылкой на проверенную играбельную страницу или при 100%.

Если `blocker` начинается с `VERIFY_FAIL`: ближайшая :30 чинит тот же PR, :40 перепроверяет тот же PR, :05 и :15 ничего нового не открывают.

## 5. Ревью Claude
- :05 каждый час читает `architecture/claude-automation-review.md`, берёт записи со статусом NEW.
- Сверяет с реальным кодом. Верно — выполняет и ставит `APPLIED` + SHA. Неверно — `REJECTED` + причина одной строкой. Нужен доступ, которого нет — `BLOCKED` + чего не хватает.
- Обработанные записи не применять повторно. Историю не удалять.
- Решения о качестве игр (PASS/FAIL) ставит только владелец.
- Claude проверяет работу раз в 2 дня и дописывает новые записи в тот же файл.
