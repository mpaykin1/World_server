# Система из семи движков World Server: как работает фундамент

Цель владельца: на нашем GitHub построить цельную систему создания игр. Последовательность: вычисления (необязательный) → драматургия → история, сценарии, диалоги → игровые механики → физика мира → визуал мира; онбординг подключает игрока к игре; pipeline связывает движки в одну цепочку.

Файлы:
- `engines.json`: определение системы (движки, форматы входа и выхода, пять пунктов готовности G1–G5, проверки, видимые шаги в играх). Правят автозадачи, когда добавляют проверки.
- `score.json`: процент. Пишет только `node scripts/engines-score.cjs --write`. Руками не править.
- `contracts/<id>.md`: контракт каждого движка (шаблон `contracts/TEMPLATE.md`).
- `cards/<game>.json`: результат запуска цепочки на карточке игры (пишет pipeline).
- `OWNER_DECISIONS.md`: вопросы владельца, блокирующие пункты.
- `manual-done.json`: отметки «выполнено» для шагов, которые нельзя проверить файлом (например замер FPS); запись: `"id": {"sha": "...", "run": "ссылка на запуск game-browser-check"}`.

Команды:
```
node scripts/engines-score.cjs                 # таблица процентов
node scripts/engines-score.cjs --next          # следующие шаги: ENGINES, VISIBLE, очередь владельца
node scripts/engines-score.cjs --run --check   # как в CI: тесты запущены, падение процента запрещено
node scripts/engines-score.cjs --write         # записать score.json (только если процент не упал)
META6_DIR=/путь/к/meta6 node scripts/engines-score.cjs   # проверки второй репы
```

Цикл пяти задач = один шаг:
1. :05 запускает `--next`, берёт шаг своей полосы: нечётный час Тбилиси ENGINES, чётный VISIBLE. Если полоса пуста, берёт другую. Если оба пусты, а в очереди владельца есть вопрос, пишет его в `last_run`.
2. :15 пишет контракт или формат шага (G1) либо каркас модуля.
3. :30 пишет модуль и тест, подключает к игре (по пункту).
4. :40 проверяет на точном SHA: `engines-score.cjs --run --check` в GitHub Actions и, если трогалась игра, `game-browser-check`.
5. :50 сливает после VERIFY_PASS, запускает `--write` (процент появляется только из скрипта) и обновляет `reuse-state.json`: `engines_lane`, `next_engine_task`, `last_run`, `run_history`.

Застой: шаг, не продвинувшийся 3 цикла подряд, режется на два меньших в `engines.json`; причина идёт в `blocker`. Блокер старше 3 часов обслуживается первым (см. `architecture/automation-config.md`).

Готовый продукт определён в `engines.json` → `product_done`. Скрипт не ставит PASS/FAIL качеству игры: это решает только владелец.
