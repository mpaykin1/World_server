# Контракт physics — G1

## Вход
Формат: `RuleSet`. Цепочка: mechanics → physics → visual. Источник — карточка игры или результат предшествующего движка. Обязательные поля определяются схемой; необязательные данные нельзя заполнять вымышленными значениями. При отсутствии обязательного поля возвращается структурированная ошибка с именем поля. Пример входа:

```json
{"loop":{"goal":"reach","action":"move","risk":"fall","result":"position","consequence":"reset","growth":"skill"}}
```

## Выход
Формат: `PhysicsConfig`. Выход передаётся следующему движку без скрытого состояния и без изменения входного объекта. Каждый результат содержит понятные поля, допускает сериализацию JSON и проверку схемой. Пример формы выхода (не утверждение канона игры):

```json
{"gravity":9.81,"step_heights":[0.3],"collisions":{"solid":true},"units":"SI"}
```

## Проверка
1. Проверить обязательные поля и типы входа; отклонять невалидные структуры с указанием пути.
2. Проверить сериализацию результата, отсутствие мутации входа и повторяемость на одинаковых данных.
3. Проверить интеграцию с соседним движком и отсутствие неразрешённых ссылок.
4. Проверить негативный случай с пустым или повреждённым входом.
5. При реализации G3 добавить автоматическую проверку в `test/engines-physics.test.js`; G1 сам по себе не означает готового модуля, теста или игры.

## Границы
Единицы измерения задаются явно: метры, секунды, м/с². Гравитация конечная, высоты ступеней неотрицательные, столкновения твёрдые. Не подменять физику только графическим перемещением; сохранять совместимость существующего golden-physics. Авторский канон, судьбы героев, качество игры и художественные решения утверждает владелец; нельзя выдавать схему за готовый сюжет или подтверждённый игровой PASS. Запрещено менять принятые версии и эталонные игровые файлы.
