# Контракт mechanics — G1

## Вход
`Scenario {scenes,events,choices,endings}` и `GameCard.genre`. Механики привязываются к выбору игрока и следам поведения, а не к фиксированному сюжету. Цель, действие, риск, результат, последствие и рост — шесть обязательных полей петли.

```json
{"genre":"exploration","scenario":{"choices":[{"type":"sacrifice","trace":"sacrifice"}],"events":[{"id":"bridge_falls"}]}}
```

## Выход
Структурированный JSON, передаваемый следующему движку через существующий интерфейс без мутации входных данных. Пример конкретной формы, не утверждённый канон отдельной игры:

```json
{"loop":{"goal":"cross_bridge","action":"jump","risk":"fall","result":"landed","consequence":"lose_time","growth":"timing_skill"},"weapons":[],"foes":[],"choiceBindings":[{"type":"sacrifice","trace":"sacrifice"}]}
```

## Проверка
Проверить шесть полей петли, отсутствие несуществующих событий, обновление следов выбора, определённый результат проигрыша и совместимость с реестром defineBiome/defineEnemy; не придумывать новые способности без сценарной причины. Ошибка входа содержит путь к неверному полю; одинаковые входы дают воспроизводимый результат. Контракт G1 сам по себе не подтверждает наличие модуля G2, теста G3 или интеграции G4/G5.

## Границы
Принятые версии игр и эталоны не изменять. Решения о художественном каноне и качестве игры принимает владелец. Для каждой следующей игры параметры выбираются заново с учётом истории и не должны превращаться в универсальный фиксированный шаблон.
