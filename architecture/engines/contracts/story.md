# Контракт story — G1

## Вход
Формат: `StoryBible`. Цепочка: dramaturgy → story → mechanics. Источник — карточка игры или результат предшествующего движка. Обязательные поля определяются схемой; необязательные данные нельзя заполнять вымышленными значениями. При отсутствии обязательного поля возвращается структурированная ошибка с именем поля. Пример входа:

```json
{"characters":[],"conflicts":{},"lines":[],"world_laws":[]}
```

## Выход
Формат: `Scenario`. Выход передаётся следующему движку без скрытого состояния и без изменения входного объекта. Каждый результат содержит понятные поля, допускает сериализацию JSON и проверку схемой. Пример формы выхода (не утверждение канона игры):

```json
{"scenes":[],"events":[],"dialogues":[],"clues":[],"pendingOwner":true}
```

## Проверка
1. Проверить обязательные поля и типы входа; отклонять невалидные структуры с указанием пути.
2. Проверить сериализацию результата, отсутствие мутации входа и повторяемость на одинаковых данных.
3. Проверить интеграцию с соседним движком и отсутствие неразрешённых ссылок.
4. Проверить негативный случай с пустым или повреждённым входом.
5. При реализации G3 добавить автоматическую проверку в `test/engines-story.test.js`; G1 сам по себе не означает готового модуля, теста или игры.

## Границы
Сцены, события, диалоги и улики обязаны ссылаться на сущности StoryBible; причинность и последовательность событий проверяемы. Запрещено сочинять канон FlyingHero и ASQURA; при отсутствии авторского решения выдавать незаполненные элементы с явным статусом. Авторский канон, судьбы героев, качество игры и художественные решения утверждает владелец; нельзя выдавать схему за готовый сюжет или подтверждённый игровой PASS. Запрещено менять принятые версии и эталонные игровые файлы.
