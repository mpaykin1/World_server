# Контракт dramaturgy — G1

## Вход
Формат: `GameCard + CalcProfile? + интервью владельца`. Цепочка: calc? → dramaturgy → story. Источник — карточка игры или результат предшествующего движка. Обязательные поля определяются схемой; необязательные данные нельзя заполнять вымышленными значениями. При отсутствии обязательного поля возвращается структурированная ошибка с именем поля. Пример входа:

```json
{"id":"ashen","genre":"adventure","ownerInput":null}
```

## Выход
Формат: `StoryBible`. Выход передаётся следующему движку без скрытого состояния и без изменения входного объекта. Каждый результат содержит понятные поля, допускает сериализацию JSON и проверку схемой. Пример формы выхода (не утверждение канона игры):

```json
{"characters":[],"conflicts":{"self":[],"others":[],"world":[],"time":[]},"lines":[],"world_laws":[],"pendingOwner":true}
```

## Проверка
1. Проверить обязательные поля и типы входа; отклонять невалидные структуры с указанием пути.
2. Проверить сериализацию результата, отсутствие мутации входа и повторяемость на одинаковых данных.
3. Проверить интеграцию с соседним движком и отсутствие неразрешённых ссылок.
4. Проверить негативный случай с пустым или повреждённым входом.
5. При реализации G3 добавить автоматическую проверку в `test/engines-dramaturgy.test.js`; G1 сам по себе не означает готового модуля, теста или игры.

## Границы
Четыре независимые линии конфликтов: герой с собой, с другими, с миром, со временем. Соблюдать docs/dramaturgy/UNIVERSAL_RULES.md; решения Q4/Q6 не подменять догадками; при неизвестном каноне вернуть вопросы, а не готовый сюжет. Авторский канон, судьбы героев, качество игры и художественные решения утверждает владелец; нельзя выдавать схему за готовый сюжет или подтверждённый игровой PASS. Запрещено менять принятые версии и эталонные игровые файлы.
