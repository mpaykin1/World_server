# Контракт onboarding — G1

## Вход
Формат: `RuleSet + StyleSheet + управление`. Цепочка: mechanics + visual → onboarding. Источник — карточка игры или результат предшествующего движка. Обязательные поля определяются схемой; необязательные данные нельзя заполнять вымышленными значениями. При отсутствии обязательного поля возвращается структурированная ошибка с именем поля. Пример входа:

```json
{"loop":{"goal":"reach"},"style":{"ui_icons":[]},"controls":["touch","keyboard"]}
```

## Выход
Формат: `OnboardingScript`. Выход передаётся следующему движку без скрытого состояния и без изменения входного объекта. Каждый результат содержит понятные поля, допускает сериализацию JSON и проверку схемой. Пример формы выхода (не утверждение канона игры):

```json
{"steps":[{"trigger":"first_move","icon":"move","effect":"pulse"}],"skip":true,"replay":true}
```

## Проверка
1. Проверить обязательные поля и типы входа; отклонять невалидные структуры с указанием пути.
2. Проверить сериализацию результата, отсутствие мутации входа и повторяемость на одинаковых данных.
3. Проверить интеграцию с соседним движком и отсутствие неразрешённых ссылок.
4. Проверить негативный случай с пустым или повреждённым входом.
5. При реализации G3 добавить автоматическую проверку в `test/engines-onboarding.test.js`; G1 сам по себе не означает готового модуля, теста или игры.

## Границы
Подсказки в игре — только иконки и анимация, без текста. Каждому шагу нужны trigger, icon, effect; обязательны skip и replay. На мобильном устройстве жесты и управление проверяются отдельно; подсказка не блокирует игровой цикл. Авторский канон, судьбы героев, качество игры и художественные решения утверждает владелец; нельзя выдавать схему за готовый сюжет или подтверждённый игровой PASS. Запрещено менять принятые версии и эталонные игровые файлы.
