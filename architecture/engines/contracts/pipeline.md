# Pipeline — контракт соединения семи движков

## Вход

`GameCard {id, genre, engines_enabled[], duration, startLocation, characters[], world_laws[]}`, `RecentGamesLog` (завершённые игры и их проверяемые решения), `randomSeed` (обязателен для воспроизводимости), `OwnerDecisions` Q1–Q12 и необязательный `CharacterSeed`. Конфигурация проекта не задаёт заранее конфликт, твист, источник помех, темп или концовку. Содержимое `STORY_ENGINE_PLAN.md` имеет приоритет перед примерами FlyingHero и ASQURA.

## Выход

`PipelineResult {gameId, seed, steps[{engine,status,input_ref,out_ref}], generated_at, errors[]}` и карточка `architecture/engines/cards/<game>.json`. Каждая запись движка содержит `ok`, `out_ref`, `source_sha`, `seed`, `verified_at` либо ошибку/недоступность. Значение `ok:true` означает доказанное фактическое подключение, а не просто существование файла. Отдельно сохраняются StoryBible, Scenario, RuleSet, PhysicsConfig, StyleSheet, OnboardingScript и использованный журнал игр. Промежуточные объекты не перезаписывают принятую игру.

## Порядок вызова

1. **calc (необязательный):** `CharacterSeed -> CalcProfile|null`. Натальная карта, Human Design и соционика служат только художественным материалом для вымышленных героев, не научной диагностикой. Пропуск не блокирует создание игры.
2. **dramaturgy:** `GameCard + CalcProfile? + RecentGamesLog + randomSeed -> StoryBible` через `createStoryBible` и `validateStoryBible`. Выбираются конфликт и его причина, персонажи, тайна, мотивированный источник помех, подсказки, неповторяющиеся твисты, варианты концовки, независимый темп четырёх этапов, виды выбора и «починка» обидного поворота.
3. **story:** `StoryBible + RecentGamesLog + seed -> Scenario`: сцены, события, короткие реплики, улики и последствия всех важных выборов. Повторно проверяются заранее посеянные подсказки и соблюдение причинно-следственных связей.
4. **mechanics:** `Scenario + GameCard.genre -> RuleSet`: игровой цикл, действия/риски/награды, оружие, враги, экономика, развилки и влияющие на финал игровые следы.
5. **physics:** `RuleSet -> PhysicsConfig`: гравитация, столкновения, размеры шага, вода и разрушения только там, где это применимо к данному проекту и его движку.
6. **visual:** `PhysicsConfig + StoryBible.world_laws + эталоны -> StyleSheet`: палитра, графические ассеты, освещение, шейдеры и иконки без правки `stand/`, `accepted/`, `reference/sumerek-golden/`.
7. **onboarding:** после механик и визуала `RuleSet + StyleSheet + управление -> OnboardingScript`: понятные графические подсказки, skip/replay, текст исключительно внутри меню ☰ справа сверху.

При каждом переходе проверяется схема входа/выхода. Нет обязательного результата — цепочка останавливается с явной ошибкой без вымышленных `ok:true`. Игры используют разные зерна и журнал завершённых игр; `nonrepeat.cjs` не допускает повторов конфликта, твистов, концовки, места финала, источника помех, одинаковых сочетаний темпа и типов «починки». Варианты финала определяются следами доверия, жертвы, правды, милосердия и бездействия.

## Проверка

### Изоляция данных адаптеров

Синхронный API `runPipeline` принимает данные, поддерживаемые `structuredClone`;
функции передаются только отдельно в реестре `adapters`. Вход запуска фиксируется
один раз. Каждый адаптер получает отдельную глубокую копию карточки, зерна,
истории и предыдущих выходов. Выход адаптера сохраняется отдельной глубокой
копией: изменение сохранённой производителем ссылки не переписывает результат
другого этапа. Это изоляция объектов данных, а не песочница выполнения кода.
Некопируемый выход останавливает цепочку с `ENGINE_FAILED` на текущем этапе.

Запрошенный необязательный calc может вернуть `{value:null}`: профиль отсутствует,
этап получает `skipped_optional`, `ok:false`, `out_ref:null`, а обязательные движки
продолжают работу с `outputs.calc === null`. Для остальных движков `null` остаётся
ошибкой. Отсутствующий адаптер запрошенного calc по-прежнему является ошибкой
конфигурации; пропуск calc в `engines_enabled` не требует адаптера.

G1: файл имеет разделы «Вход», «Выход», «Проверка». G2: `lib/engines/pipeline.cjs` экспортирует стабильный CommonJS API. G3: `node --test test/engines-pipeline.test.js` доказывает порядок вызова, пропуск calc, воспроизводимость по seed, отказ при ошибке, недопущение ложного `ok` и работу без запрещённых файлов. G4/G5: после реальной интеграции первая и вторая игры получили отдельно проверенные карточки с ссылками на конкретные результаты. `META6_DIR=<клон meta6> node scripts/engines-score.cjs --run --check` проверяет ворота и запрещает падение процента. Игровой браузерный тест проверяет результат на точном HEAD; окончательный PASS/FAIL графики оставлен владельцу.
