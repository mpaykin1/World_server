# Контракт visual — G1

## Вход
Формат: `PhysicsConfig + StoryBible.world_laws + эталоны`. Цепочка: physics → visual → onboarding. Источник — карточка игры или результат предшествующего движка. Обязательные поля определяются схемой; необязательные данные нельзя заполнять вымышленными значениями. При отсутствии обязательного поля возвращается структурированная ошибка с именем поля. Пример входа:

```json
{"gravity":9.81,"world_laws":[],"referenceIds":[]}
```

## Выход
Формат: `StyleSheet`. Выход передаётся следующему движку без скрытого состояния и без изменения входного объекта. Каждый результат содержит понятные поля, допускает сериализацию JSON и проверку схемой. Пример формы выхода (не утверждение канона игры):

```json
{"palette":[],"tiles":[],"sprites":[],"lighting":{"fog":true},"ui_icons":[]}
```

## Проверка
1. Проверить обязательные поля и типы входа; отклонять невалидные структуры с указанием пути.
2. Проверить сериализацию результата, отсутствие мутации входа и повторяемость на одинаковых данных.
3. Проверить интеграцию с соседним движком и отсутствие неразрешённых ссылок.
4. Проверить негативный случай с пустым или повреждённым входом.
5. При реализации G3 добавить автоматическую проверку в `test/engines-visual.test.js`; G1 сам по себе не означает готового модуля, теста или игры.

## Границы
Визуал обязан уважать геометрию коллизий, утверждённые эталоны и слойность: дальний фон, средний план, передний план, экран. Никакого текста и чисел поверх игры; информация — в меню ☰. Эффекты оптимизируются без удаления принятых элементов. Авторский канон, судьбы героев, качество игры и художественные решения утверждает владелец; нельзя выдавать схему за готовый сюжет или подтверждённый игровой PASS. Запрещено менять принятые версии и эталонные игровые файлы.
